# Handoff: continuing Agent Orange on another PC

Paste everything below the line into a new Claude Code session opened in this repo.

---

You're picking up Agent Orange work from a session on another PC. Read this whole file before doing anything. Memory from the other PC doesn't come with it, so the rules below are the ones that matter.

## What Agent Orange is

A Windows desktop app (WPF, .NET 10, in `client/`) for making games with AI agents, synced through a small Rust + Postgres server (`server/`). Each project is one game with a folder and a GitHub repo. Its pages cover the game's design: a node-based GDD board, plus Characters, Levels, Assets, Mechanics and References. Agents work on the game through the app and drive the creative tools it sets up, such as Godot, Unreal, Blender, ArmorPaint, Aseprite and Material Maker, over MCP. It isn't a chat box with extras. The app's own screens come first, and agent chat comes later.

## We are dogfooding

This phase is about **using Agent Orange to make three small, complete, original games**: a 2D Godot game, a 3D Unreal game and a web game. The agents are the app's user. A game may be made only *through* Agent Orange. When the app can't do something the game needs, stop the game work and build that feature, so the gaps become the roadmap. Normal tools are fine for building Agent Orange itself.

- **Game 1 is the web game, now 3D.** Its project in the app is **Animal Planet**. In the user's words: "a really simple game where you are a cute 3d character.. and you walk around on a 3d mini-globe.. kind of like 動物の森 but you are on a tiny globe". The user created the project themselves.
- **Who decides what:**
  - The user owns game design and the app's direction.
  - Ordinary product and technical calls are yours, so make them and build instead of asking.

## How to work (the user's rules)

- **Tiny visible pieces.** Work in a running dev build so the user sees each change. Don't grill the user with questions or mock up the whole app.
- **No automated tests of any kind until v1.** If a check really can't be avoided, use headless mode (`AgentOrange.exe --headless <data> <script> <out>`, debug builds only). Never touch, capture or take over the user's screen or dev window.
- **Pushing:**
  - Push to `main` without asking.
  - Every push ships a release (Velopack, mandatory updates), so batch small edits.
  - Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **No secrets in the repo, ever.**
  - The repo is public, and that includes its history and releases.
  - Before each commit, scan the staged diff for private addresses and names: 192.168.x, 100.x.x.x, machine names, user names, emails.
  - Turn the hooks on after cloning: `git config core.hooksPath .githooks`. The private-words list in `.git/private-words` is local to each PC, so ask the user to recreate it there.
- **Never create real GitHub repos in checks.** No blank repo URL and no "Yes, create it". Never send Git a bad credential.
- **Bugs:** fix them, or at least file a GitHub issue right away. No "for later" lists. Never put private items in public issues.
- **No council loops.** Fix things directly. If there's a review, get all its findings in one pass.
- **Windows:** the app must allow several windows open at once.
- **The agent files folder:** load agent tools and skills from `~/.agent-orange` (`~/.agent-orange-dev` for dev builds). Never load them from a provider's login folder, which is shared with the user's own Claude Code, Codex and T3 setups.
- **Look and feel:** the user dislikes the current look and colors. Leave the restyle alone until they bring it up.

## Running the dev build

```
dotnet watch --project client --non-interactive
```

- **Data:** the dev build keeps its data in `%APPDATA%\AgentOrange-Dev`, separate from the installed app. On a new PC, point the dev build at the same server as the installed app (Settings) so no data is lost.
- **Hot reload:** `client/HotReload.cs` redraws the page after each change. Adding new files makes `dotnet watch` restart the window, so warn the user first.

## Where we left off (2026-11-13)

Everything is merged and pushed. Nothing is waiting on any branch.

**Built so far:**
- **Tray:** closes to the tray, with an Open/Close menu and a badge count. The icon was generated by Codex.
- **Project overview:**
  - Alpha/Beta/Demo/Production stage toggle in the header. Each stage keeps its own boards, and a project can add, rename, copy and delete stages.
  - Progress tiles for Tasks done and Assets delivered.
  - Section cards for Overview (the board once called GDD), Story, Characters, Levels, Assets, Mechanics and References.
- **Section pages:** no title, and a back button that returns to the project page.
  - **Overview:** a node board.
  - **Story, Characters, Levels, Mechanics:** pages of cards (story beats, characters and so on), each card with a picture and a board of its own.
  - **Assets:** a page of cards like the others. Each asset also has a type (2D, 3D, Audio or Other kinds, as GamePipe had), what it belongs to (a story beat, character, level or mechanic, picked from a searchable list), and tags, all given in the form that adds it. They're kept in `asset_details`, apart from the card. Tags are the project's own (`asset_tags`): an asset only ticks them from a list, and they're made, renamed and deleted only in the tag editor (Edit tags on the Assets page, or in the tag list). The page filters by type and tags (an asset shows when it has the type and every tag chosen), and can't be reordered while filtered. Every asset's board shows its deliverable as a block with a dotted outline, fixed in the top right corner (`client/NodeCanvas.Deliverable.cs`). It is not a node. Only a person fills it, by clicking it and choosing the file. It's a file the game itself uses, already in the project's folder (any kind, anywhere in it, such as Unreal's .uasset). Nothing is ever copied or sent to the server, which the user disliked in GamePipe: `asset_deliverables` records only its path, size and SHA-256, and the file travels with the repo. Cards show a delivered dot, and the overview's Assets delivered tile counts them. Never expose filling it to agents.
  - **Tasks:** an asset with a Deliver by date (in its form, picked from a month that opens in place) is a task, and it's done when it's delivered. Nothing else makes a task and nothing is ticked, unlike GamePipe's separate task nodes. The overview's Tasks done tile opens the Tasks page (`client/MainWindow.Tasks.cs`), grouped Overdue, Today, This week, Later and Done. Dates are calendar days (yyyy-MM-dd), not moments.
  - **References:** still empty.
- **Node boards (`client/NodeCanvas*.cs`):**
  - Nodes are added the way Blender does it: Shift+A opens a list, and the node lands at the cursor. Node types are built **one at a time, in the order the user picks**.
  - Title node: no border or background, pin at the bottom.
  - Rich Text node: a button bar, Markdown as it's typed, height you can drag.
  - Image node: from a file, a paste or a drop, resizable.
  - Multi-select to move nodes together, and cutting links by dragging across them.
  - The add list (`client/NodeCanvas.AddList.cs`) is searchable, with groups: Primitives (Title, Rich Text, Image) and References (Story Beat, Character, Level, Mechanic, Asset). A reference node stands for one card in the board's stage (`client/NodeCanvas.References.cs`). Once its card is picked it never changes: double-clicking opens that card's board, and another card needs a new node. Asset boards don't offer References. On a story beat's, character's, level's or mechanic's board, the Asset node lists only the assets that belong to it, and typing a new name adds an asset that already belongs to it.
- **Agents window (`client/AgentsWindow.cs`, `client/AgentConversation.cs`, `client/MainWindow.Agents.cs`):** conversations down the side by project, the open one's timeline, and a message box. Designed after T3 Code (cloned and studied, not copied): tools used between messages fold into one line such as "Read 3 files, ran 2 commands", streamed words are drawn every 50 ms, only changed parts of the timeline are redrawn, the latest 20 turns are drawn with earlier ones a click away, and it follows the end unless scrolled up.
  - Each conversation runs `claude -p` with stream JSON both ways, kept running between messages, as the Claude Agent SDK does. Permission requests (`control_request` / `can_use_tool`) show as Allow / Don't allow cards, and AskUserQuestion as answerable question cards. Edits in the folder and the app's editors' MCP tools are allowed without asking.
  - Every message starts with an `<agent-orange-view>` block from `MainWindow.DescribeView()`: the project, stage, folder, page, card and every node on the open board with what's selected. Every session gets `AgentBriefing.cs` as `--append-system-prompt-file`: what Agent Orange is, that the agent does the work in the tools, never fills deliverables, and which tools are set up.
  - Conversations are saved in `<agent folder>/conversations/`, stay on each PC, and keep running with the window closed. The tray badge counts ones that finished or want something while unseen.
  - Not built yet: Agent Orange's own MCP server, so the agent can read and change boards, cards and assets (next), model and effort pickers, Markdown in replies, and images.
- **Tool forks:**
  - Settings › Editors › Tools installs and updates the user's forks from each fork's newest GitHub release, through the gh CLI login, into `%LOCALAPPDATA%\Programs\<Name>`.
  - The forks: `kansai-gaijin/armorpaint`, `kansai-gaijin/aseprite` and `kansai-gaijin/material-maker`, each with MCP added.
  - Releases are current for all three.
  - Each fork keeps all its work on its default branch. Release ArmorPaint and Aseprite with their `release.ps1`. Material Maker releases from a GitHub workflow on every push to `master`.
- **Agent sessions get only Agent Orange's own setup, for any provider:**
  - **MCP:** sessions get only the MCP servers set up in the app, written to `<agent folder>/mcp/claude.json`. Claude Code runs with `--strict-mcp-config --mcp-config <file> --setting-sources project,local`.
  - **Skills:** sessions get only Agent Orange's own skills, from `<agent folder>/skills/<name>/SKILL.md` (Settings › Agents › Skills, with an Open folder button). For Claude Code they're copied into a session-only plugin, passed with `--plugin-dir` and shown as `agent-orange:<name>`.
